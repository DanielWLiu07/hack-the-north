## Root cause, in Seer's words

**Root cause identified.**

The 6 occurrences of `camera_unavailable — /dev/v4l/by-path/x did not open` are **not real hardware failures** — they're noise generated by a unit test.

**What happens:**
1. `test_an_unopened_camera_is_named_and_the_rest_still_capture` (line 151 of `tests/test_robot_capture.py`) deliberately makes `cam2.open()` throw `CameraUnavailable("cam2", "/dev/v4l/by-path/x did not open")` to verify the rig handles missing cameras gracefully.
2. `CaptureRig._mark_unavailable()` calls `obs.robot_failure("camera_unavailable", ...)` — this is the same path real hardware failures take.
3. The `no_live_sentry` autouse fixture (`monkeypatch.setenv("SENTRY_DSN", "")`) is supposed to prevent live events, but it only patches the *env var*. If the Sentry SDK was already initialized with a real DSN (from the developer's shell environment before pytest started), the active SDK client is unaffected — so real events get sent.

**Why `sentry_events` tests work correctly but this one doesn't:** The `sentry_events` fixture explicitly calls `sentry_sdk.get_global_scope().set_client(None)` on teardown. The `no_live_sentry` fixture does not, leaving the live client active.
