# `scripts/`

| file | purpose |
|---|---|
| `bootstrap_pi.sh` | Clone BB quickstart, install deps, copy `robot/`, install the systemd unit, set static IP. **Not written** — `push_to_pi.sh` below is how `robot/` reaches the Pi today. |
| `provision_pi_tailscale.sh` | **The robot link, step 1** (docs/33): join the Pi to the tailnet with an auth key — no browser on the robot. Over SSH, or `--print` a block for a teammate's shell / a keyboard. `--wifi "SSID" "pw"` gives the Pi internet first and runs detached, rolling back if the join fails. Then records the Pi's `100.x` and switches `.env` to it. |
| `pi_link.py` | `PI_HOST` switchable between LAN and tailnet: `.env` keeps both address pairs, `use lan\|tailnet` repoints `PI_HOST` + `LAPTOP_IP` + `RERUN_ADDR` together, `status` probes both, `discover` finds `bracketbot` without DNS, `auto` picks whichever answers. No consumer changed. |
| `push_to_pi.sh` | rsync `robot/` + `obs.py` to the Pi, build a `--system-site-packages` venv (BB's `cv2`/`pyrealsense2` stay visible), install `requirements-pi.txt`, import-check. `--start [--sim]` / `--stop` / `--log`. Never pushes `.env`. |
| `verify_robot_link.py` | **The proof** that the link works: path (direct / DERP-relayed / LAN) · `/healthz` · SSE framing + clock pairing · `Last-Event-ID` resume with no gap or duplicate · reboot detection · keepalives · an N-second soak · `/stream` · optional real capture. Exit `0` only against another machine; `2` = passed but the target was this laptop. |
| `robot_sentry_watch.py` | **Sentry watching the robot from outside** — the failures a process cannot report about itself. Every 5 s: unreachable · server down · camera unavailable · IMU feed null (`telemetry_unfed`: every capture would be rejected) · tap stalled / starved · source errors · dropping · clock skew · restarted. Debounced; ONE issue per incident (`obs.robot_failure`, last 40 health snapshots as breadcrumbs + the last frame the camera sent), and `… recovered after N s` when it clears. No cron monitor — the plan's one belongs to the watch loop. Probes are `sentry-trace …-0` (unsampled). State → `~/.cache/gitspace/robot-watch.json`, which `/telemetry` shows. `--once`, `--dry-run`. Runs in tmux `robot-watch`. |
| `watch_robot_link.sh` | Live tmux pane: both addresses, is `bracketbot` on the tailnet and direct or relayed, SSE event rate, and the one command that fixes whatever is wrong. Read-only. |
| `capture_to_recording.py` | **The live robot → a perception recording** (docs/34): one gated `POST /capture` written as exactly what `perception/pipeline.py` reads — the robot's JPEG bytes, its calibration, and the **measured** mount (pitch 38.1° / 1.59 m, not bbos's 33° / 1.55 m), then **self-levelled** on the near floor per capture (bounded ±6° / ±8 cm; the nominal mount is kept beside it). Each capture is recorded in Elasticsearch (`room-clouds`; `--no-index` to skip). `--n N --every S` takes several and prints how well each agrees with the one before — on an untouched scene that table is the noise floor. `--compare A B` does the same for two existing recordings, no robot (`--json`). `--check-desk [DIR]`: is a desk where `room.yaml`'s zone expects it, and if not, what to move and by how much. Retries a 409 `capture_rejected` three times, never fakes one; a 403 = the robot's `ROBOT_ALLOW` does not list this laptop. |
| `room_live.py` | **The front door: capture → scan → git** (docs/34). `new <name>` makes an INSTANCE — a normal git repo under `~/.cache/gitspace/rooms/<name>/`, first capture, first commit; `status` / `commit -m` / `snapshot` / `watch [--every S] [--commit]` each take a capture, scan it through the real pipeline (`ROOM_SCANNER=perception:<recording>`) and let `room status` / `room commit` do the rest; `cloud --ref REF` writes the point cloud as it was at any commit; `log` · `diff` · `list`. Every commit carries `cloud/current.ply` (coloured, one point per 2 cm cell, ~2 MB) beside the object YAML; the recordings (`<name>.recordings/`) and the full-resolution model of every capture (`<name>.scene/*.ply` + `.png`, `latest.*`) sit BESIDE the repo, and the commit message carries the capture id. Captures are indexed in Elasticsearch; commits are published only with `--repo ./room.git` (instances run `ROOM_ES=off`). The pose is not tracked: never move the robot within an instance. |
| `bbos_map.py` | **The room model the ROBOT already builds, brought to the laptop** (docs/34 §2, docs/20 Fact 3). `pull` reads bbos's `mapping.voxels` over `GET /map/voxels` (3 cm coloured voxels in the SLAM world frame, bbos's floor label, the robot's pose) → `~/.cache/gitspace/maps/<stamp>/`; `objects` / `diff` separate and compare what stands in it; `scan --repo ROOM` is the product path (this map → `perception/bb_source.scan_into_bb`), `--frame` adds the head camera so new objects get names — only from a frame that provably lines up with the map (`frame-check`: the picture and the number, with the heading turned 90/180/270° as the control); `layer` adds the camera's 1 cm points and the floor objects in the map frame; `surface` measures the table's zone. Nothing on the robot is written or restarted. |
| `floor_objects.py` | **The things standing on the floor that 3 cm maps and cluster() lose** — a can, a crisp bag — from one stereo capture: height above a robust floor, an image-texture gate (blank lino has 3–6 cm of correlated floor noise, so height alone cannot find a 13 cm can), a saturation seed for colourful packs under the height threshold, then physical tests (on the floor, free-standing, not a piece of the building). Finds a 13.5 cm can to ~1.5 m and a colourful chip bag lying flat to ~1.3 m; never a floor-coloured book or cable; the limits table is in the docstring. `RECORDING --out overlay.jpg [--json] [--all] [--confirm-with OTHER]`. `room_live.py add` runs it on each capture and places the results in the map frame. |
| `room_explore.py` | **Turn and drive around, so `add` has more to add.** `--spin K` first turns on the spot through K headings (a full circle) and at each, standing `--dwell` s (3), takes the FULL add — the map plus the camera's layer from that heading (dense points, floor objects, and the `cap_NNNN` recording `bbos_map.py scan --recording` names objects from), or one line saying why the layer was skipped — `--spin 6 --minutes 0` is that alone, the robot never leaves its spot; then bbapps/nav's own swept rectangle over the room (the newest map's `bounds_m`, or `--area` / `--around R`), then its patrol, for `--minutes` (3), with `room_live.py add` run map-only every `--every` seconds (30) WHILE it drives — /scene and /robot fill in as it goes. Prints the plan (area, lanes, pose, SLAM state, bus voltage) and moves nothing without `--go` AND `clear` typed at its prompt (a pipe is a refusal); refuses in one line unless SLAM is localized, no job is running, the area is ≥ 1 m × 1 m after a 0.3 m shrink, the robot stands inside it, and robot.server's `/healthz` `bbos.power` is fresh (null or > 30 s old = the base daemon is silent). Stops, always with `halt()`: on a SLAM reset, Ctrl-C, the hard ceilings `--max-minutes` (10) / `--max-metres` (60, from pose deltas), the nav stack silent 15 s, or `bbos.power` going stale; then one last add. Logs what it is doing every 5 s (goal, pose, metres, volts), the voxel delta and commit of every snapshot, and a start / min / end voltage trail (no cutoff: nobody has stated a floor). Posts the pose as `nav` events to `$ROOM_WEB_URL/api/edge/event` at 2 Hz so `/robot` shows the robot moving. A failed add is a log line, not a stop; a failed trip is a RobotError, filed like every other, exit 1. Tested against `fake/bbsim.py` only (`--snapshot-dir` and `--healthz` stand in for what the fake does not serve). |

## Model weights — the contract

Weights live in `$MODELS_DIR` (default `~/.cache/gitspace/models`), **outside the repo**.
The bootstrap drops a `gitspace_env.pth` into the venv that sets `YOLO_CONFIG_DIR` and
`YOLO_OFFLINE=1` for every Python process, so BB-style code works unchanged and offline:

```python
YOLO("yolo11s-seg.pt")   # resolves from $MODELS_DIR/weights — no network, no cwd copy
```

`YOLO_OFFLINE=1` means a weight that was never downloaded **fails fast** instead of hanging on
venue wifi. To fetch a new one on a good network: `YOLO_OFFLINE=0 python -c 'from ultralytics
import YOLO; YOLO("yolo26l-seg.pt")'`, or add it to `YOLO_WEIGHTS` and re-run the bootstrap.

SAM 3 is meant to run on **Baseten**. `--with-sam3` pulls `sam3.pt` (gated, ~3.5 GB) plus the
CLIP tokenizer that Ultralytics would otherwise `pip install` from GitHub at runtime.
